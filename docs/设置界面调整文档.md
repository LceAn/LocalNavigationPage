## 一、设置界面总体结构

当前设置面板是一个居中模态对话框（`#settings-container` > `#settings-box`），宽屏下为「左侧标签导航 + 右侧内容」的两栏网格，窄屏下退化为顶部横向标签 + 单栏内容。

**标签页（7 个）**：

| # | 标签 | ID | 主要内容 |
|---|------|----|---------|
| 1 | 链接与分组 | `links-tab` | 统计卡片、搜索/筛选工具栏、链接分组列表、链接编辑弹窗、分类管理弹窗 |
| 2 | 外观 | `appearance-tab` | 主题模式、首页视觉、内容显示 |
| 3 | 布局 | `layout-tab` | 界面布局、首页组件 |
| 4 | 首页内容 | `homecontent-tab` | 时间与日期、天气显示、网站设置、首页工具栏 |
| 5 | 搜索引擎 | `search-tab` | 引擎列表、默认与测试、使用说明 |
| 6 | 数据 | `data-tab` | 导入导出、书签导入、数据安全、存储信息 |
| 7 | 关于 | `about-tab` | 版本号、特性、快捷键、仓库链接 |

面板顶部有标题栏（`settings-header`）和跨标签的设置项搜索框（`settings-searchbar`）。

## 二、信息架构问题（IA）

### 2.1 「首页内容」与「布局」「外观」边界模糊，存在跨标签重复语义

**现状**：
- 「外观 → 内容显示」(`appearance.display`，index.html:550-603) 与「布局 → 界面布局」(`layout.interface`，index.html:615-707) 都是"页面长什么样"。
- 「首页内容」标签里同时混入了**纯内容**（时间/日期/天气/网站标题）和**工具栏开关**（`homecontent.toolbar`，index.html:915-994），后者本质是"首页组件显隐"，与「布局 → 首页组件」(`layout.components`，index.html:710-752) 语义高度重叠——后者管的是"显示信息条/搜索框/最近使用"。
- 「显示搜索框」（layout.components，index.html:730-738）与首页工具栏里的若干开关在用户心智里属于同一类操作，却被拆到两个标签。

**问题**：用户想"关掉首页某个东西"时，需要在「布局」和「首页内容」两个标签间反复横跳，认知负担大。注释本身也承认有过迁移（index.html:549、912 有迁移遗留注释）。

**调整建议**：按"是什么层"重新归口，确立唯一归属原则：

| 拟定归属 | 收纳内容 |
|---------|---------|
| **外观** | 一切"视觉表现"：主题、背景风格、玻璃质感、动画、紧凑模式、缩略图、搜索按钮图标样式 |
| **布局** | 一切"放哪儿 / 显不显"：页面位置、密度、分组展开行为、极简模式、**所有首页组件/工具栏开关**（含信息条、搜索框、最近使用、昼夜按钮、回到顶部、设置按钮、自定义按钮） |
| **首页内容** | 一切"显示什么文字/数据"：时间日期格式、天气、网站标题文案 |

即：把「首页内容 → 首页工具栏」整段（index.html:915-994）迁入「布局」标签，与 `layout.components` 合并为统一的"首页组件"分区；「首页内容」只保留时间/天气/网站标题。

### 2.2 「布局 → 界面布局」里混入了极简模式的子配置

**现状**：「时钟方向」「时钟位置」两个选项（index.html:677-704）通过 `data-gate="minimal-mode-toggle"` 只在极简模式开启时显示，但其父分区标题是"界面布局"，语义割裂。

**调整建议**：把极简模式及其时钟方向/位置单独提升为一个「极简模式」分区（`layout.minimal`），让"开关 + 子配置"内聚，避免用户在折叠状态下看不到子项的归属。

### 2.3 标签数量偏多，"关于"占用一个一级入口性价比低

**现状**：7 个标签里"关于"信息量小（版本、4 条特性、3 个快捷键、2 个链接），却和"链接管理""数据"并列。

**调整建议**：将"关于"降级为设置面板标题栏右侧的一个小图标按钮（或 footer 链接），把一级标签收敛到 6 个以内，宽屏左侧导航更聚焦核心配置。

## 三、交互与逻辑问题

### 3.1 设置项搜索：体验可用但反馈较弱

**现状**（main.js:801-877）：搜索通过遍历 `.settings-section` / `.option-item`，按文本匹配决定显隐，并用 `settings-search-count` 显示"X 项"。仅在**当前激活标签页**内搜索（main.js:801 取 `tab-content.active`）。

**问题**：
- **跨标签搜不到**：用户在「外观」标签里搜"回到顶部"（该选项在「首页内容」标签）会得到空结果，且没有"是否切换到其他标签"的提示，容易误以为没有这项设置。
- 空结果时只显示 `settings-search-empty`（settings_box.css:261-274），无"在其它标签中查找"的引导。

**调整建议**：
- 搜索时改为**全局匹配**：命中项所属标签若非当前标签，自动切换到该标签并滚动/高亮命中分区；或至少在空结果提示里列出"此项位于 [XX] 标签"并提供跳转。
- 搜索激活时自动展开所有被命中的 `settings-section`（当前折叠态下命中分区内的项不可见）。

### 3.2 分区折叠状态持久化依赖 `data-section-id`，迁移兜底脆弱

**现状**（main.js:3840-3885）：折叠态存于 `collapsedSections`，键优先取 `data-section-id`，取不到时回退到 `.section-title-left span` 的中文文本。

**问题**：
- 一旦分区标题文案改动（如本调整文档建议的归并/重命名），用旧中文标题持久化的折叠态会失效（虽然这是可接受的降级，但会造成"我明明折叠了，刷新又展开"的困惑）。
- `search.list`、`search.help`（index.html:1003-1066）等分区**没有** `data-section-id`（其 `.section-title` 直接含 `<span>`，无 `.section-title-left` 结构），取 id 时走文本兜底，与其它分区结构不一致。

**调整建议**：为所有 `.settings-section` 补齐 `data-section-id`（含 search/data 各分区），统一用稳定英文 id 作为持久化键，彻底移除对中文文案的依赖。

### 3.3 极简模式子项联动用 `data-gate` 手动控制，缺少可发现性

**现状**（main.js:2448）：开启极简模式时遍历 `.minimal-sub-option[data-gate=...]` 显隐。子项默认 `display:none`，用户在折叠状态下根本不知道"还有时钟方向/位置可调"。

**调整建议**：子项做成"灰色禁用态"而非完全隐藏（保留可见但 `pointer-events:none; opacity:.4`），或在开关旁加一行说明"开启后可配置时钟方向与位置"，提升功能可发现性。

### 3.4 首页工具栏开关缺少"隐藏全部后的恢复路径"提示的一致性

**现状**：仅 `show-settings-btn` 下方有提示"隐藏设置按钮后，可按 Ctrl/Cmd + , 重新打开设置"（index.html:976-979）。但其它工具栏开关（如"回到顶部""布局调整"）隐藏后无类似说明。

**调整建议**：在分区底部统一加一句"工具栏按钮隐藏后，可通过设置或快捷键恢复"，避免用户关掉后找不到入口。

### 3.5 「打开时展开首个分组」开关语义与命名不符

**现状**（index.html:647-656）：开关 id 是 `default-expand-all`，标签文字是"打开时展开首个分组"，但 `getSetting('defaultExpandAll')` 用于"展开全部/首个"的逻辑分散在 main.js:2515、5053。命名（expand-all）与文案（首个）不一致，易误导。

**调整建议**：统一语义——若只展开首个，则 id/文案/key 三者都改成"首个"；若意图是全部展开则文案改"展开全部分组"。明确后再动代码。

## 四、视觉与样式问题

### 4.1 「链接与分组」标签使用了独立的 Google Material 配色体系，与其余标签割裂

**现状**（settings_box.css:622-1261）：`#links-tab` 重新定义了 `--google-blue/--google-border/--google-text` 等一套变量，链接卡片、统计卡、工具栏全部走这套 Material 风格（直角更小、阴影更平、蓝色 `#1a73e8`）；而外观/布局/数据等标签走全局 `--primary-color`（紫蓝 `oklch(62% 0.19 268)`）。

**问题**：同一设置面板内出现两套视觉语言（紫蓝圆角 vs Google 蓝扁平），切换标签时有"换了个应用"的断裂感。

**调整建议**：让 `#links-tab` 复用全局 token（`--primary-color`/`--primary-light`/`--rounded-*`），仅保留其独有的列表/拖拽结构样式，去掉 `--google-*` 变量层。深色模式同步收敛（settings_box.css:1237-1261 的 `body.dark-mode #links-tab` 覆盖也可随之简化）。

### 4.2 分区标题点击热区与折叠箭头视觉权重

**现状**（settings_box.css:1587-1627）：`.section-title` 整行可点折叠，箭头 `ri-arrow-down-s-line` 在折叠时旋转 -90°。但 `search.list`/`search.help`/`data.*` 等**部分分区没有折叠箭头图标**（对比 index.html:1003-1006 的 `search.list` 标题里无 `.section-collapse-icon`），导致"有的能折叠有的不能"的不一致。

**调整建议**：统一所有 `.settings-section` 的标题结构（都有 `.section-title-left` + `.section-collapse-icon`），折叠行为一致；或明确"哪些分区不可折叠"并去掉其 `cursor:pointer` 与 hover 态。

### 4.3 选项卡片网格在不同分区密度不均

**现状**：`visual-options-grid` / `button-settings-grid` 是 2 列（settings_box.css:1775-1785），`layout-options` 是单列纵向（settings_box.css:1769-1773）。同样形态的开关项，在外观标签是 2 列、在布局标签是 1 列，视觉节奏不统一。

**调整建议**：对"开关型 option-item"统一用 2 列网格，"下拉/输入型 option-item-stacked"用单列，按控件类型而非分区决定列数。

### 4.4 「关于」标签的版本检查状态无明确终态

**现状**（index.html:1287-1289）：版本检查初始显示"检查更新中..."（`ri-loader-4-line ri-spin`），但 HTML 里没有"已是最新/有新版本"的静态结构，完全依赖 JS 动态注入 `#version-check-status`。若 JS 出错或网络失败，会一直停留在"检查更新中..."。

**调整建议**：增加超时兜底（如 8 秒后显示"暂时无法检查更新"），并提供"手动检查"按钮，避免假死态。

### 4.5 弹窗（modal）层级与设置面板层级

**现状**：`.modal-overlay` z-index 1100（settings_box.css:1266），`#settings-container` z-index 1000。链接编辑/分类/搜索引擎/自定义按钮 4 个弹窗都是从设置面板内唤起的二级模态，叠加在设置面板之上。深色模式下 `#links-tab .links-search` 背景为 `rgba(30,41,59,.88)`，而 modal 背景模糊 8px，多层叠加时背景模糊较重，文字对比度需复核。

**调整建议**：实测深色模式 + 极简模式叠加场景下二级模态的可读性；必要时降低 modal 的 `backdrop-filter` 强度或给 modal-content 加实色底。

## 五、可访问性问题（A11y）

### 5.1 对话框焦点陷阱不完整

**现状**：`#settings-container` 标注 `role="dialog" aria-modal="true"`，但未在 main.js 中看到明确的 focus trap 实现（Tab 不会被困在面板内，可能 Tab 到背景元素）。

**调整建议**：打开设置时记录触发元素、将焦点移入面板、拦截 Tab 在面板内循环、关闭时焦点归还触发元素。

### 5.2 分区折叠缺少 `aria-expanded`

**现状**（settings_box.css:1625-1637 + main.js:3840）：折叠仅靠 `.collapsed` 类切换 `display`，`.section-title` 未标注 `role="button"` / `aria-expanded` / `aria-controls`，屏幕阅读器无法播报展开收起状态。

**调整建议**：`.section-title` 加 `role="button" tabindex="0" aria-expanded="true/false" aria-controls="<content-id>"`，并补 `keydown`（Enter/Space）触发折叠。

### 5.3 主题选择、搜索引擎列表等为自定义可点 `<div>`，缺 role/键盘支持

**现状**：`.theme-option`（index.html:455-477）、`.search-engine-item` 等是 `<div>` 靠 click 触发，无 `role="button"` / `tabindex` / 键盘事件。

**调整建议**：改用 `<button>` 或补齐 ARIA + 键盘处理（与《前端整改报告》3.2 一致）。

### 5.4 设置搜索框无 `aria-live`

**现状**：搜索结果数量 `#settings-search-count`（index.html:224）动态更新，但无 `aria-live="polite"`，屏幕阅读器不会播报"找到 X 项"。

**调整建议**：给 `#settings-search-count` 与空结果提示加 `aria-live="polite"`。

## 六、工程与一致性

### 6.1 设置项默认值分散，无单一真相源

**现状**：默认值散落在各处 `getSetting('xxx', defaultValue)` 调用里（如 main.js:2515、2577、5053 的 `defaultExpandAll` 默认 `false`），HTML 里又用 `<input checked>` 表达默认值。两处默认值需人工保持同步，易漂移。

**调整建议**：建立单一 `SETTINGS_DEFAULTS` 对象作为唯一真相源，初始化时据此设置 DOM 的 `checked`/`value`，读取时统一 `getSetting(key, SETTINGS_DEFAULTS[key])`。

### 6.2 缓存破坏参数仍是手写日期串

**现状**（index.html:15-18、1352-1353）：`?v=20260627-minsettings` 手动维护。

**调整建议**：（与《前端整改报告》4.5 一致）引入构建期内容哈希，或至少在调整文档落地时统一刷新一次版本串。

### 6.3 设置面板 CSS 单文件过大

**现状**：`settings_box.css` 约 3500 行，混合了容器、表单、链接管理、弹窗、多 URL 下拉、数据、关于、响应式等所有内容。

**调整建议**：按《前端整改报告》3.5 的方向，拆分为 `settings/base.css`、`settings/links.css`、`settings/modals.css`、`settings/data.css` 等，便于按标签维护。
